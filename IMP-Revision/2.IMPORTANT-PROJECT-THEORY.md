##### **\*1.Can you explain your chatbot project to me?**

###### 1.I developed a knowledge-based chatbot using Python and Django.

###### 

###### 2.The chatbot allows users to ask questions and get answers from a knowledge base stored in a SQLite database.

###### 

###### 3.It has three main UI pages: a home page, a knowledge-base page, and an update page.

###### 

###### 4.On the home page, when a user asks a question, the application searches the database using Django ORM.

###### If the question exists, the stored answer is displayed.

###### 

###### 5.If the question doesn't exist, the chatbot allows the user to teach it a new answer. That answer is then stored in the database,

###### so the chatbot can provide it the next time the same question is asked.

###### 

###### 6.Users can also update existing answers or delete knowledge from the knowledge base.

###### 

###### 7.For the backend, I used Django and Django REST Framework. I used Django models and ORM for database operations,

###### serializers for API validation, and a service layer to keep the business logic separate from the views.

###### 

###### 8.I also created REST API endpoints for GET, POST, PUT, and DELETE operations and tested them using Postman and automated API tests.







##### **\*2.Why did you choose Django for this project instead of Flask?**

###### 

###### 4.So I chose Django because its built-in features and structured architecture helped me to maintain and extend project.

##### **9.What is the difference between authentication and authorization (permissions) in Django/DRF?**

##### **12.Why did you use redirect() after POST operations in your chatbot?**



###### I used redirect() after POST operations because I followed the **POST-Redirect-GET (PRG) pattern**.

###### 

###### After processing the POST request, the application redirects the browser to another URL, which results in a new GET request.

###### 

###### This prevents the form from being resubmitted accidentally when the user refreshes the page.





##### **13.What is a Django migration, and why do we use makemigrations and migrate?**

###### Django migrations are used to apply changes made to our models to the database.

###### 

###### When I change models.py, I first run makemigrations. This creates a migration file that describes the changes.

###### 

###### Then I run migrate, which applies those changes to the actual database.





##### **14. What is the difference between request.POST and request.GET in Django?**

**This data is sent by client**

###### request.GET is used to access data sent through the **UR**L, usually from a GET request.

###### 

###### request.POST is used to access data submitted through an **HTML form** using the POST method.

###### 

###### For example, in my chatbot, when the user submits a question through the form, I use request.POST.get("question") to get the question entered by the user.

###### 

###### 

###### request.GET → data from the URL/query parameters

###### request.POST → data submitted through a POST form

###### 

###### Traditional HTML forms support mainly:

###### 

###### GET

###### POST

###### 

###### So in our browser UI, when we wanted to delete or update, we used a POST form, and then our Django view decided what action to perform.







##### **15.What is a Django session, and why did you use sessions in your chatbot?**



###### A Django session is used to store temporary data.

###### In my chatbot, I used sessions mainly because I follow the POST-Redirect-GET pattern. After a POST request, I stored the question and answer in the session, redirected the user, and then displayed that data after the GET request.

###### 

###### I also used a session value called pending\_question when teaching the chatbot. It remembers which question the user's new answer belongs to.

##### **17.What is CSRF, and why did you use {% csrf\_token %} in your Django forms?**



###### CSRF stands for Cross-Site Request Forgery.

###### 

###### Django uses a CSRF token to protect POST forms from unauthorized requests coming from another website.

###### 

###### In my chatbot, I used {% csrf\_token %} inside my POST forms because Django requires CSRF protection for these forms.





##### **18.What is the difference between GET and POST from a security and data-handling perspective?**

###### GET is mainly used to retrieve data. The data is usually sent through the URL, so it should not be used for sensitive information.

###### 

###### POST is mainly used to send data to the server, such as creating a new record. The data is sent in the request body, so it is better suited for submitting data.

###### 

###### In my chatbot API, I used GET to retrieve knowledge and POST to create new knowledge.

###### 

###### One important point: POST is not automatically secure just because the data is in the request body.

###### HTTPS is what protects data while it travels over the network.





**19.What is the difference between PUT and PATCH in Django REST Framework?**
PUT is used to update an existing resource, generally by sending the complete data.
---

###### 

###### PATCH is used for a partial update, where we update only specific fields.

###### 

For example, if a knowledge record has both a question and an answer, PUT can update the complete record, while PATCH can update only the answer.

###### PUT → complete update

###### PATCH → partial update

400 → Bad input

##### **1.What is Django?**

Django is a Python web framework

Django = Python framework that gives you the tools and structure to build web applications.

**Problem:** Building a web application from scratch requires handling URLs, requests, database, security, HTML, etc. yourself.

**Django solves** this by providing a ready-made structure and tools for building web applications with Python.

Django reduces the amount of web-development work you need to build yourself.





##### **Main features of Django**

Django provides ready-made features that make web development easier:

\- ORM → Work with databases using Python instead of writing SQL.

\- Admin Panel → Manage database data through a ready-made UI.

\- URL Routing → Connect URLs to views.

\- Authentication → Login, logout, users, passwords, etc.

\- Templates (DTL) → Create dynamic HTML pages.

\- Forms \& Validation → Handle and validate user input.

\- Middleware → Handle common request/response tasks.

\- Security → Built-in protection against common web attacks.

\- Migrations → Manage database structure changes.





##### **2.Django Project vs App → What problem does it solve?**

Problem: A large application can become difficult to organize if everything is kept together.

Django separates functionality into apps.

Example:

Project

│

├── chatbot app

├── users app

└── payments app

**Project = entire application.**

**App = one specific functionality.**



**Project vs App**

Project			    **|**	App

Entire website		    **|**	One feature/module

Created once		    **|**	Multiple apps in one project

django-admin startproject   **|**	python manage.py startapp





##### **3.📋 MVT Pattern**

M → Model     →  Database (data layer)

V → View      →  Logic (what to do)

T → Template  →  HTML (what to show)





**MVT vs MVC**

MVT (Django)	  MVC (Other frameworks)

Model		   Model

View		   Controller

Template	   View



Django's View = MVC's Controller



**Problem:** If database code, application logic, and HTML are mixed together, the code becomes difficult to maintain.

Django separates them: MVT separates different responsibilities and keeps Django code organized.







##### **3. What is Middleware?** 

**Problem:** Some tasks need to happen for many or all requests, instead of writing the same code inside every view.



For example:

Request

&#x20;  ↓

Middleware → authentication/security/session etc.

&#x20;  ↓

View

&#x20;  ↓

Response



So:

**Middleware provides a common processing layer between the request and response.**







##### **4.What is a template?**

**A template is an HTML file that contains the design of a web page, plus placeholders where Django can put data.**

example:

**Dynamic data** = data that can change depending on the user/request/database.



Template = HTML design + placeholders for data.

Dynamic data = data that Django can provide/change at runtime, often from a database.

##### **7.API**

**API = Application Programming Interface**

**Simple Definition**

API = Agreement between two applications to share data

One app asks → other app responds with data



Problem it Solves:

Your Python backend wants to talk to a React frontend

Your mobile app wants data from your server

How do they communicate? → API!



Real Life Analogy

You (customer)     →  Waiter  →  Kitchen

Frontend/App       →  API     →  Backend/Database



You don't go to kitchen directly

App doesn't touch database directly

API sits in between!



##### **8.What is a REST API?**

Problem it Solves:

APIs needed rules — everyone was making them differently

REST gave a standard way to build APIs

Now everyone follows same rules → easy to understand!



**Simple Definition:**

REST API = API that follows REST rules and Uses HTTP methods to perform actions on data





##### **9.What is Django REST Framework?**

Simple Definition:

DRF = Django toolkit to build REST APIs

Instead of returning HTML → returns JSON data



DRF provides features like **API endpoints, serializers for data validation, and handling HTTP methods** such as GET, POST, PUT, and DELETE.



Problem it Solves

Django is for websites with HTML pages

But what if React / Flutter / Mobile app needs **just data (JSON)?**

DRF makes it easy to build REST APIs in Django!
