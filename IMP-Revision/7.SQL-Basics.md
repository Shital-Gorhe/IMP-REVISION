##### **Primary Key** —

solves duplicate/identification problem



student\_id	name

1		Rahul

2		Gauri

3		Rahul





student\_id is the Primary Key.

It gives every row a unique identity.



So the problem it solves is:

**"How do I uniquely identify each record?"**





##### **Foreign Key** — 

solves relationship problem



**Students**

student\_id	name

1		Rahul

2		Gauri





**Orders**

order\_id	student\_id

101		1

102		1

103		2





Here student\_id in Orders is a Foreign Key.

It connects the order to the correct student.



So the problem it solves is:

**"How do I connect records between two tables?"**





###### **Primary Key: uniquely identifies a record.**

###### **Foreign Key: connects one table to another using a key.**

##### **GROUP BY**

##### **🔗 JOIN:**

**JOIN  →  "Gives matching records from two tables"**



Problem it Solves

Student data is in one table

Course data is in another table

You want both together — JOIN connects them!



Assume These Tables

students table          courses table

\--------------          -------------

id  name  course\_id     id  course\_name

1   Rahul  2            1   Python

2   Priya  1            2   Java

3   Amit   3            3   HTML





###### **✅ Types of JOIN**

###### **INNER JOIN** — only matching rows

sql

SELECT students.name, courses.course\_name

FROM students

INNER JOIN courses

ON students.course\_id = courses.id;



Output:

Rahul  →  Java

Priya  →  Python

Amit   →  HTML



Only rows where match exists in BOTH tables



###### **LEFT JOIN** — all left + matching right



SELECT students.name, courses.course\_name

FROM students

LEFT JOIN courses

ON students.course\_id = courses.id;



All students shown — even if no course match

Missing course shows NULL





###### **RIGHT JOIN** — all right + matching left

sql

SELECT students.name, courses.course\_name

FROM students

RIGHT JOIN courses

ON students.course\_id = courses.id;



All courses shown — even if no student enrolled





###### **FULL JOIN** — everything from both

sql

SELECT students.name, courses.course\_name

FROM students

FULL OUTER JOIN courses

ON students.course\_id = courses.id;



All rows from both tables — NULL where no match





##### **🆚 JOIN Types — Visual**

INNER JOIN   →   A ∩ B    only matching

LEFT JOIN    →   A + matched B

RIGHT JOIN   →   B + matched A

FULL JOIN    →   A + B everything





**🧠 Quick Summary**

Concept	Purpose	Keyword

GROUP BY	Summarize/group data	 		COUNT, SUM, AVG

HAVING		Filter groups	       			After GROUP BY

INNER JOIN	Only matching rows from both		ON

LEFT JOIN	All left + matched right		ON

RIGHT JOIN	All right + matched left		ON

FULL JOIN	Everything from both			ON



**🎯 One Line Each**

**Where**

GROUP BY   →  group rows and calculate totals per group

HAVING     →  WHERE but for groups

INNER JOIN →  only rows that match in both tables

LEFT JOIN  →  all from left table, matched from right

RIGHT JOIN →  all from right table, matched from left

FULL JOIN  →  everything from both tables





##### **WHERE vs HAVING**

**WHERE				 |	HAVING**

Filters rows before grouping	 **|**	Filters groups after grouping

Cannot use aggregate functions	 **|**	Can use COUNT, SUM, AVG

WHERE marks > 60		 **|**	HAVING COUNT(\*) > 5
